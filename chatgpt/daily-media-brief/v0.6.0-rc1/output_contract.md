# Daily Media Brief · PoC Output Contract

版本：v0.6.0-rc1  
候選修訂：poc-calibration-g1-g7-output-2026-08-27

本檔統一承辦待審輸出、LINE 可貼草稿與內部稽核軌跡。
承辦可見 Gate 統一使用 `G0–G8`。

## 1. 最終待審輸出結構

固定順序：

1. `合標準（X 則）`。
2. `候選新聞（X 則）`。
3. `今日總摘要`。

`合標準` 對應 internal alias `CORE`。
`候選新聞` 對應 internal alias `EXTENDED`。
承辦不需要看到 CORE／EXTENDED 這兩個工程詞。

### 合標準（X 則）

```text
合標準（X 則）

1. 新聞原始標題
摘要：50～100 字繁體中文摘要。
連結：https://example.com/article

2. 新聞原始標題
摘要：50～100 字繁體中文摘要。
連結：https://example.com/article
```

### 候選新聞（X 則）

```text
候選新聞（X 則）

1. 新聞原始標題
摘要：50～100 字繁體中文摘要。
連結：https://example.com/article
```

候選新聞代表具有比較、延伸、前瞻或追蹤價值，交由承辦決定是否採用。
它不是「錯誤新聞」，也不可混入已被 G2／G3／G5／G6 排除的內容。

### 今日總摘要

```text
今日總摘要
250 字以內，整理本批合標準＋候選新聞的主要趨勢、重大事件與值得留意方向。
```

今日總摘要不得新增新聞原文沒有的事實。

## 2. G7｜數量與交付完整度

G7 使用 G1 已經設定的 `target_total_count`。
G7 不得自行決定新的目標則數。

G7 PASS／DEGRADED 檢查：

- 是否已達承辦設定的目標總則數。
- 合標準則數。
- 候選新聞則數。
- 每一則是否有原始標題。
- 每一則是否有 50～100 字摘要。
- 每一則是否有完整原文連結。
- 是否有 250 字內今日總摘要。
- 若不足目標，是否清楚揭露實際則數與已使用的來源／時間擴張。

不足則數可以標 `G7 DEGRADED`。
不得為了讓 G7 PASS 把排除內容塞進來。

## 3. G1｜承辦先決定執行範圍

開始搜尋前顯示或確認：

```text
本次日期範圍：今日
目標新聞則數：＿＿則
主題：依目前 profile
```

若外部 PoC 尚未設定目標則數，系統詢問一次：

`今天希望最後看到幾則新聞？`

若使用者有保存的 profile，未來可以直接使用 profile 內的預設值。

## 4. 待審狀態摘要

承辦需要看得到：

```text
本次範圍：今日
目標：X 則
合標準：X 則
候選新聞：X 則
實際總數：X 則
G0 PASS · G1 PASS · G2 PASS · G3 PASS · G4 PASS · G5 PASS · G6 PASS · G7 PASS/DEGRADED · G8 WAIT
```

如有補搜，再補：

`來源擴張：有／無`。
`時間擴張：今日／48h／72h`。

## 5. 人工命令

`刪除 3、7`：移除指定新聞並重新編號。
`第 5 則換掉`：只補搜同一主題。
`資安再找兩則`：增加本次 runtime override，不改永久 profile。
`只留合標準`：移除候選新聞並接受總則數下降。
`候選新聞少一點`：只調整候選區，不降低合標準品質。
`為什麼這則是候選`：依 G4 與 audit 說明。
`通過／定版／可以了`：G8 PASS。

## 6. LINE 可貼版

LINE 仍使用同一批待審資料。
不重新判斷新聞。

每則固定為：

```text
新聞原始標題
摘要：50～100 字。
連結：https://example.com/article
```

合標準與候選新聞分段顯示。
今日總摘要放在兩區之後。

## 7. 內部稽核軌跡

每個 run 至少留下：

- run_id。
- G1 日期範圍與 target_total_count。
- active brief profile。
- query plan 與語意延伸詞。
- source coverage。
- candidate／excluded ledger。
- 合標準／候選新聞／排除數量。
- G0–G8 結果。
- 本批與跨日去重。
- 人工刪除、替換、補搜與通過事件。

舊 regression 若仍使用 Q0–Q8，只在內部 mapping 中保留，不出現在承辦輸出。

## 8. 發布邊界

本輸出是待審／可貼內容。
Skill 不自行操作 LINE 群組，也不把「承辦通過」自動當成「實際已發布」。
未來若要知道真正是否分享，需要外部 publish event 或人工回寫。
