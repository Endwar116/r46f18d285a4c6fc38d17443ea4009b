INPUT｜承辦怎麼用

給我今日輿情 15 則
給我今天資安輿情 10 則

日期、目標則數、主題可以直接從指令帶入；未來也可由個人／科別 Profile 帶預設值。

PROCESS｜系統怎麼處理

完整拆成 G0–G8：執行準備、日期與目標則數、搜尋、來源、事實、業務相關性、去重、摘要、數量與交付完整度、人工確認。

腳本邏輯與所有參數都放在「系統架構圖」。

→

OUTPUT｜最後長什麼樣

合標準＋候選新聞＋今日總摘要。

每則：原始標題＋50～100 字摘要＋完整連結。

最後：250 字內今日總摘要。

Input 使用方法。

給我今日輿情 15 則 給我今天 AI 輿情 12 則 今天只看資安，候選新聞最多 3 則

若目標則數未提供，PoC 需決定由 Profile 帶預設值，或由系統詢問一次。目前設計原則是目標則數由承辦決定。

Output 固定結構。

合標準（X 則） 1. 新聞原始標題 摘要：50～100 字繁體中文摘要。 連結：https://... 候選新聞（X 則） 1. 新聞原始標題 摘要：50～100 字繁體中文摘要。 連結：https://... 今日總摘要 250 字以內。

預期發展。

Phase 1：先讓目前承辦能以一句話啟動並完成待審流程。

Phase 3：同一批資料可產生承辦清單、科長一頁式與處長 Executive Brief。

SYSTEM ARCHITECTURE · PROCESS DEEP VIEW

架構與系統流程

這一頁專門解釋 Process。

每個 Gate 拆成目的、腳本邏輯、參數與決策人，作為下一步細部討論規格。

完整處理鏈。

G0 執行準備→G1 日期＋目標則數→關聯搜尋／語意延伸→G2 來源與證據→G3 具體事實→G4 業務相關性→G5 重複判斷→G6 摘要忠實度→G7 數量＋交付完整度→G8 人工確認

關聯搜尋／語意延伸。

primary_keyword → synonym → professional_term → related_concept → project_concept → event_type / related_entity → query_plan → candidate_news → G4 relevance

因此標題沒有「資安」「AI」等文字，只要事件概念實質相關，也能先被召回，再由 G4 判斷。
